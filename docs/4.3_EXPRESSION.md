# 4.3 Expression

*The relationships an agent cannot see, cannot express, and cannot keep current, and why the cure is a better notation, not a bigger window.*

This is the third entropy, and the third component of the context: the counterpart to the Entropy of Comprehension (the comprehension section) and the Entropy of Trajectory (the trajectory section), part of the `CONTEXT = COMPREHENSION + TRAJECTORY + EXPRESSION + AGENCY` the whole-context section defines. Where comprehension carries the intent and trajectory the lineage, expression carries the structure: the relationships of the work, in a form the agent can read before it acts and reproduce in what it builds. Its failure shows up most plainly in what the agent produces (both because it could not perceive the structure it was extending and because the channel it produces through is linear when the structure is not), yet the cure is still something the agent is given, which is why it belongs in the context at all.

The complaints from the opening section that this section answers are the ones that survive every correction. You confirmed the agent understood the task. You watched it explain the plan back, coherently, and the explanation was right. You approved each step. And the thing it built is still structurally indefensible: a module that swallowed responsibilities belonging elsewhere, a function written a second time fifty lines from the first, a boundary crossed so quietly no single diff shows it. None of this is a failure of understanding. The understanding was confirmed. It is a failure to give that understanding a shape, and it is the one entropy that fails even when the other two are held.

> The agent can hold the idea. It cannot hold the shape of the idea.
> The gap between what it understands and how it organises what it builds is the Entropy of Expression.

The parallel to the comprehension section is exact: the Entropy of Comprehension is the gap between what was asked and what was interpreted; the Entropy of Expression, the gap between what is understood and what is organised. Both are discontinuities the agent crosses confidently, because nothing in the loop renders the gap visible.

## The file is a blob, the relationships invisible

A traditional agentic system gathers files, pulling each one in as though it changes as a whole and its relationship to the files around it were obvious or irrelevant. Neither is true. A source file is not an atom; it is a container of scoped items: classes, functions, enumerations, each with its own reasons to change, its own dependents, its own life. The agent is handed the container and left to infer the contents' relationships from a flat reading. The structure lives in the AST, and the AST is exactly what the interface discards.

The same defect afflicts prose. A markdown document is gathered as a blob, and its main message can stay true while a paragraph inside it has gone stale, stale enough to derail the task that trusts it. The interface assigns equal weight to everything inside a boundary, every line of the file and every paragraph of the doc, and so cannot tell the load-bearing chunk from the dead one.

So the agent does the only thing the interface permits: it zeroes in on the region the task names, because that is the only scope it can hold without conflating concerns it cannot see at once. That local focus is reasonable, and it is exactly how the damage starts. Code written for a later, higher-level goal is invisible from inside the local task, so the agent writes it again, slightly differently, under a different name. Over a long enough session most agents converge on a single scope, one file or one module, and begin shoving every new item into it, because that is the only structure they can keep in view. The cost is more than bloat: it is the loss of a canonical source of truth. When one concept lives in three places, no decision can be made cleanly, because no one, agent or human, can say which copy counts. And the next model inherits the mess as the example of how this codebase is done, and extends it faithfully. The disorder becomes the convention.

This is clearest outside code. Ask an agent to write a book and the early chapters come easily, while the dependency graph is still small. Then the work stalls, not for lack of capability, but because each new chapter demands re-reading everything before it to avoid retconning a fact from chapter two or destroying a setup the ending depends on. The agent has no structural view of the narrative, only the linear text, and the only safe continuation is total reconstruction of the prior state before every step. That is neither reasonable nor scalable, and it names the missing capability exactly: not memory size, but structural expression. The problem was never specific to code. It is the management of information that is complex, non-linear, and non-repetitious, where nothing repeats and everything refers.

## Two axes, and two directions

The blob and the book are not two complaints but two cells of one structure. Expression varies along two axes, and each axis runs in two directions; naming the grid is what keeps the component from becoming the thing it indicts: a boundary that holds too much and weighs it all the same.

The first axis is **access**: the granularity and currency of the pointer, whether the agent refers to the scoped item or the whole container, and whether that reference is held in delta against the moving work or frozen at the moment it was drawn. The stale paragraph and the swallowed module are access failures; the pointer was too coarse to name what mattered, or too old to know it had changed. The second axis is **modality**: the form a relationship is encoded in, and whether that form matches its shape. Prose for a narrative, a dependency graph for a call structure, a chart for a proportion, a pointer to an image for all an image carries at a glance. The book written one line at a time is a modality failure; the structure was a graph and the channel was a line.

Each axis runs in two directions, because expression is not only what the agent is handed to *read* but what it is made to *produce*. Reading here is the understanding of structure, a different thing from comprehension's understanding of intent; the agent that grasped the task exactly can still misread the shape of the code it edits. Producing is the expression of structure, the organisation of what it builds. The same two axes govern both:

| | **Read**: understand structure | **Produce**: express structure |
|---|---|---|
| **Access** | a stale paragraph inside a still-valid file; the blob hiding its own AST | every new item shoved into one module; the duplicate written because the original was out of view |
| **Modality** | a proportion handed over as a paragraph of numbers rather than a chart | a graph-shaped argument forced out one line at a time |

This is why modality is not separable from compression: it is how that compression is achieved for a given class of relationship. A pointer to an image does enormous work for almost no tokens because the image *is* the abstraction; the modality is the selective precision, chosen to carry the most relational payload per token for the shape at hand. The wrong modality does not merely read worse; it spends more of the window to say less.

> Expression governs the form and the granularity in which relationships are encoded, for reading and for production.

That line is also the membership test, and it earns its keep by what it turns away. Whether an agent infers a task or a deterministic procedure enumerates its cases is a question of which *engine* runs, not which *form* the relationships take: adjacent to expression, not inside it. Whether an action is permitted (by what authority, under what governance) belongs to agency. Expression is only ever the shape information is given and given back in; the discipline of that boundary is what lets the component stay precise about so much.

## The precision–abstraction tension

There is a reason this is hard, and at first it looks like a wall. To express a multidirectional relationship precisely seems to require context no window will reliably hold, which drives toward a tempting but wrong conclusion: that the fix is for models to simply hold more, and hold it better. That conclusion is the trap, the same false remedy as the ever-larger prompt wearing the costume of memory.

The escape is abstraction, and it works because precision and abstraction are not opposites. A good abstraction is selective precision: exact about the relationships that matter, silent about everything else. An entity-relationship diagram is simultaneously abstract and exact; a dependency graph states its edges precisely while discarding every line of implementation behind them. The agent never needed the detail. It needed the relational skeleton, and the skeleton abstracts compactly enough to survive the window.

> The entropy is the cost of an unresolved tension between precision and abstraction.
> Too precise, and the expression overflows the window: the false pull toward more memory.
> Too little abstraction, and it collapses back into blobs and prose.

The failure is bidirectional, like the under- and over-specification of intent in the comprehension section, and in both, the remedy is never *more*. It is the right form.

## The abstraction does not have to be perfect

What makes this tractable rather than aspirational: the abstraction does not have to be perfect. It has to be cheap, familiar, and current. Any modern model already knows how to read an ERD, an AST, a call graph; the notation sits in its training corpus a million times over. It does not need a flawless model of the workspace. It needs a precise, abstract thing to look at, and the value of that thing is decided almost entirely by the accuracy and consistency with which it is kept.

This is why the obvious half-measures fail, and they fail in opposite directions. A one-off Mermaid diagram has the abstraction and it rots: written once, frozen on disk, it carries no delta against the work that kept moving after it, until it says what was true on Monday and the agent falls back to prose. An `ls` dump has the currency, it is always true, and no precision: it names the files and says nothing about what relates to what. The artifact the agent needs is the one neither of these is: precise, abstract, and current, a representation maintained in delta against the evolving work. This is compression in the exact sense the whole-context section requires: the structure held precisely while spending almost none of the window, the only reason a comprehensive context fits at all, because the same relationships in prose would overflow it. And it keeps its own clock: expression tracks the rate the structure changes, faster than provenance accretes, slower than the directive moves, which is why a representation frozen at the speed of either goes stale.

## The convention that makes it worse

The field's instinct, confronted with this, runs in exactly the wrong direction. The dominant convention, visible in the "use this `CLAUDE.md` for perfect results" genre and in system-prompt scaffolding alike, is to constrain the agent: never act without authorisation, change only what you were told, ask before you explore. Its cost is a double irony. The constraint is adopted to prevent one unintended consequence, unauthorised action, and it introduces another: it is hostile to multidirectional relationship-awareness, collapsing the one capability the agent might be uniquely good at, spotting a relationship a person would miss. The risk it guards against is real, so the choice is not cargo-cult; it is a rational choice with an unpriced cost, and the cost stays invisible because the agent complies agreeably and never reports what the constraint cost it.

The error is conflating perception with action. By forbidding unauthorised doing, the convention also blinds seeing. The two can be separated, and separating them is the whole move:

> Decouple seeing from doing. Let the agent's perception of relationships run free (bounded, but free) while its authority to act stays gated. The autonomy risk lives in the doing; the value lives in the seeing; the convention sacrifices the second to contain the first.

## The intervention, and the remedy that is not one

The insufficiency of prose for relationships is not a discovery of the agentic era. It is the reason an entire lineage of notation exists: Venn diagrams, entity-relationship diagrams, UML, dependency graphs, and state machines, each a purpose-built language for a class of relationship that paragraphs express badly or not at all. The agent is denied that recourse, made to operate through the one interface the field already judged inadequate for relational structure, linear prose and the file-as-blob, and then blamed for the relational failures the interface guarantees.

What the component needs is an artifact that can be examined cheaply, before the agent acts: a model of the workspace's relationships that answers the questions the agent currently answers by invention, what exists, what does not, how much of this should be built, and how it is likely to be used. It must be precise (resolved to the scoped item, not the file), abstract (a skeleton, not a transcript), and current (held in delta against the work, not frozen at the moment it was drawn). No tool we know of provides this, and the absence is why the most-offered remedy is the one that cannot work: as the Entropy of Expression rises, the only remedy on offer is a larger and larger prompt, the user explaining the structure for the Nth time or pointing the agent at a document that has quietly gone stale. Each escalation is prose attempting to carry what prose cannot. It is the same false remedy as "write better prompts," for the same reason: the notation that failed cannot be the notation that fixes it.

---

The model did not get worse. The shape of the work outgrew the only interface it was given to hold it. What detects the failure after the fact is the structural and lexical instrumentation of the slop section; what would prevent it is the artifact this section specifies and that no system, to our knowledge, yet ships. Precision about relationships, paid before the agent acts, is cheaper than the duplication it prevents, and the difference compounds across every commit written against a shape no one could see.
